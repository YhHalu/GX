## 3. 当前速度接口与参数

- `CSGO(float cn1, float cn2)`：0～100 的参考速度百分比，不是 RPM 或 PWM。负数、超过100、非有限值返回 HAL_ERROR。
- 两路100%参考值均为6000四倍频计数/秒，不代表电机物理最大速度；`CSGO(30,30)` 对应各1800计数/秒。
- 当前 Motor_UARTInit 自动配置计数闭环。PI 参数 Kp=0.05、Ki=0.4、Kd=0、D滤波0.03s，积分和输出0～300（PWM千分比，即最高30%），sign=+1。采样约10ms、使用实际dt。
- RPM API 为 Motor_SetTargetsRPM / Motor_SetTargetRPM，须先用 Motor_PIDConfigure 设置实际 CPR/方向/对应增益；不能把计数模式增益原样用作RPM模式。CPR仍未知，RPM=计数/秒×60/CPR，RPM增益=计数模式增益×CPR/60。
- 手动 Motor_SetDutyPercent(-100～100) 控制两路 PWM，Motor_SetSpeed(-1000～1000) 控制单路；会退出对应 PID。停止、刹车、释放也退出该路闭环。运行时换向先停止并等待降速。
- 串口主循环有命令租约和故障状态，直接在该模式中混用手动控制需明确模式管理；一般测试通过串口完成。

## 4. 串口使用与 Type-C 结论

USART1：PA9=TX，PA10=RX，115200、8N1、无流控。3.3V USB-TTL：模块TX接PA10，RX接PA9，GND共地；电机独立正常供电。U9的2脚=GND，3脚=PA9，4脚=PA10；图上 USART2_TX 网名误导，实际 MCU PA9 对应 USART1。

- 本轮改为 UART v2：`@2,TYPE,SID,SEQ[,参数]*CRC`＋真实 LF，兼容 CRLF，整帧≤192字节。CRC-16/CCITT-FALSE 覆盖 @ 与 * 之间原始字节。
- HELLO 新会话→INFO→STOP→零 ACK→WAIT_START→SW2→IDLE 才允许运动；READY 仅为上电提示。SID 为32位大写十六进制随机会话，SEQ 为递增uint32；同序号重复帧不续租；同目标的新序号正常续租，旧会话/序号不能运动。旧四位数字协议退出当前源码。
- SET 两路目标整数0～1000对应0～100%参考速度，0.1%分辨率；仍调用CSGO，不改变PI/PWM参数。ACK回显接受目标；100ms周期STATUS增加实际四倍频计数速度（×10整数）、有效位、采样年龄、状态/故障和uptime。
- 非零运动租约500ms；半帧100ms；坏CRC/字段、越界、旧序号/会话、UART错误/溢出/接收滞留、关键回执拥塞停止锁存。STOP仅在条件健康时清故障。控制零接口失败时另尝试直接停止两路，不返回成功ACK。
- RX256项；关键TX8槽（可排7帧）；STATUS独立保留最新一份，关键回执优先。重复故障合并，首次无法入队则在空间恢复后补报。活动发送或持续BUSY达100ms中止并停机。
- 香橙派单线程拥有串口；普通请求最多一个等待ACK，100ms发送最新目标、300ms ACK超时、300ms应用请求有效期。故障撤销目标并最多三次尝试STOP；recover后只有新请求可运动。zero_only禁止非零目标。
- CRC不提供身份认证或抗恶意重放。保护仍依赖前台循环；正式固件未新增IWDG、电流保护或独立急停。
- 按键实现位于 motor_command.c，Motor_UARTPoll 在处理已收数据后轮询PB2；gpio.c和CubeMX的PB2配置同步为下拉输入。不新增工程源文件引用。启动/恢复长按、抖动、故障时按下及按键前半帧均不能放行；未放行的非零SET报START_REQUIRED/FAULT，不缓存。STOP及零SET始终可用于停止。重复按下仅保持许可，不用作急停。
- 固件标识 GXUART2_BTN；上位机2.1.0识别WAIT_START并提供wait_for_start(timeout=30)。新建会话撤销许可，故障恢复要重新按键；旧GXUART2仍兼容但无此保护，旧2.0.0上位机不能使用按键固件。

2026-10-02 已视觉核对本地原理图：USB3 Type-C D+ (USB_DP) → U3 PA12/33脚，D− (USB_DN) → PA11/32脚，没有 USB 转串口芯片。当前未实现 USB CDC，插Type-C不会因USART1代码而出现COM口。原理图未画 D+ 到3.3V的1.5kΩ上拉；R41/R42是CC的5.1kΩ下拉，不能替代D+上拉。若做Type-C通信须核对实物上拉/数据连接并增加CDC，不能仅凭图断言实物是否已补电阻。本轮未修改USB固件。

## 电机测试汇总（2026-10-01）

### CSGO 写在哪里

- 文件：`../Core/Src/main.c`，`/* USER CODE BEGIN 2 */` 区域，CubeMX 的 MX_TIM2/3/4_Init 和 Motor_SystemInit 成功之后。

- while(1) 的 USER CODE BEGIN 3 中持续执行 Motor_Update。目标设置一次即可；不要在更新循环中加入长延时，采样间隔超过 100ms 会停止正在闭环的电机。
- 当前尚未调用 Motor_PIDConfigure，直接把 0 改成 3 会返回 HAL_ERROR 并进入现有 Error_Handler，不会开始闭环。

### 速度数值范围

- 单位是减速箱输出轴 RPM（转/分钟）；3 RPM 是约 20 秒一圈。支持小数，如 3.5f；正负指定方向，0 停止并退出对应闭环。
- 当前软件没有按电机型号设置最大 RPM，仅校验有限浮点数、配置和换向条件。因此不能把浮点数的表示范围当成电机可运行范围，也不是限定 -100～100。
- 实际可用范围是电机在当前电压、负载和 PWM 上限下能稳定达到的转速；型号的额定转速、减速比和实测尚缺，不能给出具体最大值。目标过高时 PWM 会达到配置上限，但实际速度不一定达到目标。
- 3 RPM 很低，是否能平稳运行需实测；当前 10ms 采样时，单个计数对应 6000/CPR RPM，低速反馈可能量化明显，不能用“没看到马上转动”判断程序无效。
- 运行中不能直接从正目标切换为负目标；先 CSGO(0,0)，等待停稳，再给负目标。

1. 先验证电机及接线：在 main.c 原 CSGO(0,0) 调用处临时替换为 Motor_SetDutyPercent(20,0)，保持返回值检查。这是 CN1 20% PWM 开环测试，不需 PID 配置；20% 是否足以起转取决于实物。再用 Motor_SetDutyPercent(0,20) 单独测试 CN2。测试时让轮子悬空，电机电源匹配额定电压。本文只记录步骤，没有把当前固件改成上电转动。

### 为什么 eide.yml 显示修改，以及头文件如何接入

- 文件真实名称是 `.eide/eide.yml`。此前确实修改过：加入 `Motor/motor.c`，补齐 `../Core/Src/tim.c` 和官方 HAL TIM/TIMEx 源文件，添加 Motor 包含目录；精简时删除 encoder.c、n20.c 的工程引用。显示修改是工程配置变化，不等于编译失败。
- 本项目 `srcDirs: []`，使用 `virtualFolder` 下的显式文件列表。只把一个新的 `.c` 文件放进目录，不代表它自动参与编译；需要把它加入源文件列表。
- `.h` 不单独编译成目标文件。我在磁盘创建 `Motor/motor.h`，把 **目录 Motor** 加入头文件搜索路径，再在使用它的 `.c` 中写 `#include "motor.h"`。
- EIDE 实际配置为 `targets → machinery → cppPreprocessAttrs → incList` 中的 `- Motor`。当前还包含 `.`、`../Core/Inc`、HAL 和 CMSIS 等目录。
- Keil 的 `Cads/VariousControls/IncludePath` 同步加入 `./Motor`，Motor 文件组加入 `./Motor/motor.c`。头文件即使没有单独显示在工程树中，编译器仍能通过包含路径找到。
- `.h` 声明接口，`.c` 实现函数。只加 `.h` 或只加 Include Path 不会把 `.c` 的实现编译链接进来；反之只加 `.c` 而未设置头文件路径，也可能找不到头文件。
- CubeMX 重新生成或重新导入工程后，核对 EIDE 和 Keil 都保留 `Motor/motor.c` 与 Motor 包含目录。不要将 `Motor/tests` 或 build 下的旧库备份加入固件源文件列表。
- `build/machinery/builder.params`、scatter 和编译命令属于生成的构建文件；常规配置应改 eide.yml/工程设置，而不是只改生成文件。

### 硬件事实与引脚映射

- 主控：U3 STM32F103C8T6；外部晶振 X1=8MHz，旁边 C14/C15=22pF。
- U7/U8 是 AT8236 功率驱动芯片，接收 MCU PWM，为电机供电并控制正反转。N20 的霍尔 A/B 是反馈信号。
- 用户电机资料：https://wiki.lckfb.com/zh-hans/tjx-tms320f28p550/module/control/n20-hall-encoder-motor.html 。已阅读，确认 A/B 为编码器、M/P 为电机供电端；其 TI 平台代码不可直接用于 STM32。

| 通道         | STM32 引脚 | 实际用途           |
| ------------ | ---------- | ------------------ |
| TIM2_CH1     | PA15       | CN1/U7 的 IN1      |
| TIM2_CH2     | PB3        | CN1/U7 的 IN2      |
| TIM2_CH3     | PA2        | CN2/U8 的 IN2      |
| TIM2_CH4     | PA3        | CN2/U8 的 IN1      |
| TIM3_CH1/CH2 | PA6/PA7    | CN1 霍尔编码器输入 |
| TIM4_CH1/CH2 | PB6/PB7    | CN2 霍尔编码器输入 |

注意 CN2 的 IN1/IN2 绑定次序是 CH4/CH3。早期将 TIM2_CH1/CH2 写成 PA0/PA1 的回答已纠正；实际必须 PA15/PB3 和 Partial Remap 1。
CN1/CN2 六脚分别是：1=AO2/BO2，2=VCC_MISC，3=编码器 CH2，4=编码器 CH1，5=GND，6=AO1/BO1。线束按信号核对，不单凭六针外形或颜色判断兼容。电机功率电源来自 VIN，经 AT8236 输出。

### 当前 CubeMX 设置

- SYS Debug=Serial Wire，禁用 JTAG 以释放 PA15/PB3，保留 PA13/PA14 的 SWD。
- RCC HSE=Crystal/Ceramic Resonator，8MHz ×9，SYSCLK/HCLK=72MHz，APB1=/2。APB1 总线 36MHz，但其定时器时钟为 72MHz。
- TIM2 Internal Clock，CH1～4 PWM mode 1，PSC=0，ARR=3599，Pulse=0，High，有效 PWM 频率 20kHz。生成代码包含 `__HAL_AFIO_REMAP_TIM2_PARTIAL_1()`。
- TIM3/TIM4 Combined Channels=Encoder Mode，TI1 and TI2，PSC=0，ARR=65535，IC1/IC2 为 Rising、Direct TI、DIV1、Filter=6。A/B 四倍频计数，不单独启用 CH1/CH2 PWM。
- 当前编码器 GPIO 是 INPUT、NOPULL。若实际电机输出开漏且无板载上拉，应在 CubeMX 中设置合适的上拉；尚未上板验证输出电气形式。
- 本方案主循环轮询，无需定时器中断或 DMA。Internal Clock 指定时器总线时钟来源，不等于内部 HSI；PWM 可以用外部 HSE 经 PLL 得到的总线时钟。

### 主程序与接口使用

main.c 先执行 HAL_Init、SystemClock_Config、MX_GPIO_Init、MX_TIM2_Init、MX_TIM3_Init、MX_TIM4_Init，然后在 USER CODE 中：

```c
/* CubeMX 的 MX_TIM2/3/4_Init 之后 */
if (Motor_SystemInit() != HAL_OK) { Error_Handler(); }
if (CSGO(30, 30) != HAL_OK) { Error_Handler(); }
/* 主循环中 */
(void)Motor_Update();
```

Motor_SystemInit 在 motor.c 封装两台电机绑定、启动 PWM/编码器、重置计数基准与记录采样时间，失败会回退已启动资源。Motor_Update 封装每 10ms 的采样。motorA/motorB、encoderA/encoderB 都由 motor.c 定义，motor.h extern 声明；encoderTick 为库内 static。初始化函数保持零占空比，当前 main.c 随后调用 CSGO(30,30)，使两台电机持续正方向 30% PWM。

| API/变量                          | 含义                                  |
| --------------------------------- | ------------------------------------- |
| `Motor_SetSpeed(&motorA, 300)`  | CN1 正方向 30% 占空比；参数不是 RPM   |
| `Motor_SetSpeed(&motorB, -300)` | CN2 反方向 30%                        |
| `Motor_Stop`                    | 两输入低，滑行停止                    |
| `Motor_Brake`                   | AT8236 两输入高，刹车                 |
| `Motor_DeInit`                  | 清零并关闭两路 PWM                    |
| `Encoder_Reset`                 | 重建计数基准，清零位置，sign=1、CPR=0 |
| `Encoder_Sample`                | 计算增量、累计位置、计数/秒和 RPM     |

- 调速范围 -1000～1000，越界限幅；正负实际转向依线序确定。换向前停止并等待负载降速，尚未实现自动减速/换向状态机。
- PWM 命令通过 CCR 预装载在下一更新事件生效，更新两通道时保护临界区；所有 API 从同一个主循环上下文调用。
- Encoder_State 中 delta 是采样增量，position 为 64 位累计值，counts_per_second 是计数/秒，rpm 是标定后的输出轴 RPM，valid 表示最近一次采样有效性。
- 默认 counts_per_turn=0，rpm 保持 0 表示未标定，不能据此判断电机静止。获得实际输出轴四倍频 CPR 后，停止状态下设置 encoderA/encoderB.counts_per_turn；反馈符号不符时设置 sign=-1。
- CPR 可由缓慢转动输出轴数圈的累计计数测量。若厂家给电机轴单通道周期数，输出轴 CPR=该周期数×4×减速比；已经四倍频的数据不要再乘 4。
- 每次采样实际变化须小于 32768 个计数。间隔大于 100ms、恰好半计数范围或累计溢出时返回无效；丢失区间不计入位置。避免主循环长时间阻塞。valid 是上次采样结果，不是自动更新的“数据仍然新鲜”标志。

# 四字符串口速度控制

## 当前实现

USART1，115200、8N1、无流控。收 ASCII 数字，不是二进制数值。前两位控制 CN1，后两位控制 CN2。

按最新需求，CSGO 的两个参数改为 **0～100% 的期望速度比例**，不再表示 RPM，也不是 PWM 占空比。原双路 RPM 接口保留为 `Motor_SetTargetsRPM`。

四字符中每台只有两位，无法直接表示三位的100。本版暂采用提议的编码：**00～99 线性映射到0～100%，99代表100%**。

```text
电机1百分比 = 前两位十进制数 / 99 × 100
电机2百分比 = 后两位十进制数 / 99 × 100
调用 CSGO(电机1百分比, 电机2百分比)
目标计数/秒 = 百分比 / 100 × 满量程计数/秒
```

每台满量程暂定6000计数/秒（已实测的参考工作点，不是测得的电机物理最大转速），在 `Motor/pid.c` 的 `Motor_FullScaleCountsPerSecond[2]` 修改；两路可分别设置。该定义对应“期望速度/参考速度范围×100”。CPR 未知，不显示虚假的实际 RPM。

| 发送文本 | 传给 CSGO 的百分比 | 目标计数/秒 CN1 / CN2 |
| --- | --- | --- |
| `0000` | 0 / 0 | 两路停止；确认并清除故障锁存 |
| `9900` | 100 / 0 | 6000 / 0 |
| `0099` | 0 / 100 | 0 / 6000 |
| `3060` | 约30.303 / 60.606 | 约1818.18 / 3636.36 |
| `9999` | 100 / 100 | 6000 / 6000 |

直接在 C 中调用 `CSGO(30, 60)` 仍是精确30%、60%，即1800、3600计数/秒；串口两位编码另经过99→100换算。`1000` 表示前两位10、后两位00，绝不表示第一台100%。不支持负数或反向字符。

软件支持表中指令，但历史实测只覆盖单路正向3000、6000计数/秒；低速、双路同时和长时间运行尚未上板验收。不要将100%速度误解为100% PWM：实测 PID 输出仍被限制到300千分比，即30%占空比。

## 分帧与返回

- 推荐每帧发送4个数字后加 LF 或 CRLF，例如 `3060\n`，收到结束符立即执行。
- 也支持严格4个数字、无结束符，收齐后空闲20ms才执行。两帧至少间隔20ms，实际建议100ms。
- 不足4位等待最多100ms；过长、非数字、半帧超时均停机并返回错误。
- 连续 `30600000` 不会猜成两条命令，按超长帧拒绝；要发 `3060\n0000\n` 或分开发送并留间隔。
- 错误后丢弃当前帧到换行或空闲边界，必须发完整 `0000` 确认，再发运动命令。
- 无校验的四字符协议无法识别“一个合法数字被干扰成另一个合法数字”，也无法保证丢字节后自动对齐。结束符、错误停机和超时只是降低风险，正式抗干扰通信仍建议带序号/CRC。

启动返回实际内置参数，例如：

```text
READY UNIT=PERCENT SCALE1=6000 SCALE2=6000 CPS KP=0.050 KI=0.400 KD=0.000 PWM_MAX=300
```

成功设置 `3060` 后返回：

```text
ACK RAW=3060 M1=30.30 M2=60.61 UNIT=PERCENT CPS1=1818.2 CPS2=3636.4 PWM_MAX=300
```

M1/M2 是设置的速度百分比，CPS1/CPS2 是目标计数/秒，**不是实测反馈**；PWM_MAX 的单位为千分比。以上数值仅是按参数计算的示例，不是新一轮电机实测记录。当前没有周期遥测，真实采样仍在 `encoderA/B.counts_per_second`。

常见错误：`FRAME`、`LENGTH`、`PARTIAL_TIMEOUT`、`LINK_TIMEOUT`、`LATCHED_SEND_0000`、`CONTROL`、`MOTOR_SAMPLE_OR_FEEDBACK`、`UART_RX`、`STALE_RX`、`TX_BACKPRESSURE`。错误回执中 M1/M2 为停止后的0，不报告失败指令为执行成功。

## 原理图接线

依据本项目 `原理图.pdf` 第1页：U9第3脚虽然标为 USART2_TX，但实际连 U3第30脚 PA9，应配置 **USART1_TX**；U9第4脚连 U3第31脚 PA10，即 USART1_RX。默认引脚功能可对照 [ST 官方数据手册 Table 5](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。

| U9 脚位 | 信号 | 连接3.3V USB-TTL |
| --- | --- | --- |
| 1 | VCC_MISC，3.3V支路 | 板子已有电源时不接 |
| 2 | GND | GND |
| 3 | PA9 / USART1_TX | RXD |
| 4 | PA10 / USART1_RX | TXD |

## 固件接入与保护

- `Motor/motor_uart.c` 独立拥有USART1初始化、IRQ及HAL回调：中断收1字节入队，主循环解析；TX为中断异步发送，固定队列保留发送缓冲直到完成，不阻塞PID。

- USART1当前由自定义文件管理，**不要同时再生成另一个 USART1_IRQHandler、huart1 初始化和HAL回调**。若以后迁移到CubeMX的usart.c，应移除自定义硬件初始化/IRQ，仅保留协议层并适配句柄，不能重复初始化。

- 运动中每100ms重发目标；**500ms没有执行成功的完整命令会停止并锁存故障**。无效数据不续租。相同目标重发不清积分。重新运动前发送0000。

- 软件停止依赖主循环执行；当前没有在正式固件新增IWDG、电流保护或硬件急停。机械安全仍需独立保护。

## 与 RPM 接口的区别

```text

Ki_RPM = 0.4 × CPR / 60
Kd_RPM = 0
```

main.c顺序执行CubeMX GPIO/TIM2/3/4初始化、Motor_SystemInit、Motor_UARTInit、CSGO(0,0)。主循环执行Motor_UARTPoll，它内部负责Motor_Update。上电不运动，接收有效指令才启用闭环。

EIDE源文件包括motor.c、pid.c、motor_command.c、motor_uart.c和HAL UART驱动，编译宏包含HAL_UART_MODULE_ENABLED。Keil源文件/宏同步添加；当前实际验证采用EIDE+ARMCC5，原uVision工程其他旧驱动绝对路径未在本次统一迁移。CubeMX重生成后须保留USER CODE并检查自定义文件、Motor包含路径、HAL UART宏。

不要同时生成另一个USART1初始化/IRQ/回调；若改成CubeMX管理串口，应迁移motor_uart.c的适配层并确保单一硬件所有者。不要让USART2占用PA2/PA3，也不要重映射USART1到PB6/PB7。

## 常用接口

- `CSGO(50,0)`：CN1为满量程的50%，当前3000计数/秒；CN2停止。
- `CSGO(0,0)`：两路停止并退出闭环。
- `Motor_SetTargetsRPM`：旧CSGO的RPM接口；必须标定真实CPR并换算增益。
- `Motor_SetDutyPercent(30,30)`：手动30% PWM，退出两路PID。
- `Motor_SetSpeed(&motorA,300)`：手动PWM千分比，即30%，不是速度。
- `Motor_Stop/Brake/DeInit`：停止、刹车、释放资源。

所有电机API由一个主循环上下文调用。首次使用自定义句柄前清零，底层初始化要求TIM2/3/4、向上内部计时、ARR1～65534、两个不同且空闲的PWM通道。

encoderA/B提供delta、64位累计position、counts_per_second、rpm与valid。CPR为输出轴每圈四倍频计数；CPR=0表示未标定，rpm的0没有测量意义。不要为所有N20假设同一减速比或CPR。

# PID 与速度接口

## 参数统一放在 pid.c

`Motor_MeasuredCountsPID` 定义在 `pid.c`、声明在 `pid.h`：Kp=0.05、Ki=0.4、Kd=0，输出及积分范围0～300 PWM千分比，derivative_tau=0.03s。速度输入为四倍频编码器计数/秒；Ki在算法内乘实际dt，不要再预乘10ms。

`Motor_FullScaleCountsPerSecond[2]` 同样在 pid.c，当前两路均6000计数/秒。它是百分比控制的100%参考速度，来自已测试工作点，不是最大速度的物理标定。修改范围后需要重新验证可达性和响应。

实测数据见 [PID.md](../PID.md)。正式工程已把TIM2改为1kHz（时钟72MHz、PSC19、ARR3599），编码器输入上拉，sign=+1；快衰减、最大30% PWM。此前只验证单路正向3000/6000、每轮2秒，未证明其他速度、双路同时或长期运行性能。

## CSGO 现在表示速度百分比

按用户最新要求，`CSGO(first, second)` 接受两个有限的0～100浮点数：

```text
速度百分比 = 期望计数速度 / 满量程计数速度 × 100
目标计数速度 = 百分比 × 满量程计数速度 / 100
```

```c
CSGO(50, 0);
CSGO(0, 100);
CSGO(0, 0);
```

依次代表CN1目标3000/CN2停止，CN1停止/CN2目标6000，两路停止。这里100%速度不等于100% PWM，输出仍限30%。越界、负数、NaN/Inf或任一路未配置时返回HAL_ERROR，先校验两路再修改目标。重复同向目标保留积分。

四字符串口把两位编码00～99映射为0～100%后调用CSGO；因此串口 `3060` 不是直接调用CSGO(30,60)。编码限制、回执和接线见 [串口通信.md](../串口通信.md)。

## 初始化与主循环

当前 main.c 已接入以下顺序，上电不自动运行：

```c
if (Motor_SystemInit() != HAL_OK) { Error_Handler(); }
if (Motor_UARTInit() != HAL_OK) { Error_Handler(); }
if (CSGO(0, 0) != HAL_OK) { Error_Handler(); }
```

`Motor_UARTInit()` 配置两路计数PI并初始化USART1。主循环持续执行 `Motor_UARTPoll()`；它处理通信、调用Motor_Update并在控制故障时锁存停机，不要再重复调用Motor_Update。

不使用串口时，在Motor_SystemInit之后分别用 `Motor_PIDConfigureCounts(&motorA, 1, &Motor_MeasuredCountsPID)`、motorB对应调用配置两路，然后主循环调用Motor_Update、由应用处理其错误。所有电机API只能在同一个前台上下文调用，中断仅放入接收队列。

若以后得到真实输出轴四倍频CPR，可用 `PID_MakeRPMConfig(cpr, &config)` 按CPR/60换算Kp/Ki/Kd，输出和积分限幅保持不变，再配置RPM接口；零CPR或空输出指针返回0。当前串口百分比控制不需要CPR，不输出伪造RPM。

## 控制与故障边界

每路PID独立：位置式P/I/D、按实际dt积分、测量微分及低通滤波、条件积分抗饱和、输出/积分限幅和非有限数值检查。更新周期至少10ms，计数窗口1个计数对应约100计数/秒的量化台阶。

控制只按目标方向输出单向PWM，超速可降至零但不反向刹车。有符号接口换向必须先置零并等待负载降速；没有机械停稳检测。百分比接口只允许正向。

采样间隔超过100ms、16位计数差恰好半范围、累计溢出、CPR/sign被外部篡改或PID计算错误时，停止活动闭环。每次实际位移应小于32768计数，否则无法唯一还原回绕。

有非零PWM而持续零净计数时累计无反馈时间；达到阈值返回HAL_TIMEOUT并停止活动闭环。非零计数重置时间；超时后不自动重启。RPM模式默认禁用这项保护以兼容极低速，可按需开启。

该保护不能区分堵转、断线或低速，也不能检测所有噪声和反向反馈；没有电流保护。USART应用另有500ms失联保护与故障锁存，恢复先发0000。所有软件超时依赖主循环，正式固件未新增硬件看门狗。

实际反馈读 `encoderA/B.counts_per_second`，并检查 `valid`；未标定CPR时 `rpm=0` 没有真实RPM测量意义。串口ACK回报的是设置值，不是实际反馈。

## 执行

在 MDK-ARM 目录运行；脚本使用本机已配置的 ARMCC 和 EIDE/OpenOCD 安装路径。先确保电机供电、接线、输出轴状态适合短时转动测试。

```powershell
python Motor/hardware/probe.py build
python Motor/hardware/probe.py flash
python Motor/hardware/probe.py measure --name new-cn1-pi3000 --channel 1 --mode pid --target 3000 --limit 300 --duration 2000 --pullups --pwm-hz 1000 --kp 0.05 --ki 0.4
python Motor/hardware/probe.py restore
```

- `open` 的 target 和 limit 单位为 PWM 千分比。`pid` 的 target 单位为编码器计数/秒，直接调用已有 PID_Update；不是输出轴 RPM，不会给编码器填入假设 CPR。
- 每次只测试一路，正向输出；最多 30% PWM、2 秒带动力阶段，前置 200ms 零输出、后置 500ms 零输出采样。无计数 300ms、采样失效或计算错误会停机。
- 使用 IWDG，按标称 40kHz LSI 配置约 500ms 超时；主循环喂狗。该诊断不能替代电流保护或机械防护。
- 开机和测试结束均不自动转动。脚本检查诊断固件标记后才写命令，并检查最终 CCR=0；发现异常运行状态会复位。正常工程仍由 EIDE 原配置构建。
- 状态 1=待命、2=运行、3=完成、4=故障。故障码 1=参数无效、2=初始化失败、3=停止命令、4=采样错误、5=无计数超时、6=反馈方向/运算错误、7=PWM 写入失败。
- `--pwm-hz` 支持 1000 和 20000，默认 20000；复现已验证的 PI 参数必须传入 1000。`--decay slow` 用 IN1 常高、IN2 反向占空比实现厂商慢衰减模式，默认 fast。改变驱动模式后不能直接沿用已测增益。
- 首轮 open-loop 故障不是 PID 整定结果；后续已获得上表的闭环数据，换算 RPM 增益仍需实测 CPR。
